# Hotel Booking Management System - Tiered Cancellation & Refund Policy\n\nThis repository contains the implementation for the Tiered Cancellation & Refund Policy feature (Jira SCRUM-36) within the Hotel Booking Management System.\n\n## Project Overview\n\nThis feature introduces a new microservice, the `Cancellation & Refund Service`, responsible for calculating refund amounts based on guest membership tiers and cancellation windows, processing refunds via a payment gateway, and providing interfaces for guests and hotel staff.\n\n## Features\n\n- **Tiered Refund Calculation:** Calculates refund percentages based on:\n    - Guest Membership Tier (Bronze, Silver, Gold)\n    - Time before check-in (7+ days, 1-6 days, <24 hours, No-Show)\n- **Payment Gateway Integration (Simulated):** Placeholder for integration with an external payment gateway to process refunds.\n- **Audit Trail:** Logs cancellation and refund transactions.\n- **Configurable Policy:** Refund rules are stored in a configurable manner.\n\n## Architecture\n\nThe `Cancellation & Refund Service` is designed as a microservice, interacting with existing booking and guest services (conceptually) and an external payment gateway. It uses a relational database for storing policy rules and refund transactions.\n\n## Setup Instructions\n\n### Prerequisites\n\n- Python 3.9+\n- Docker (for containerized deployment)\n- `pip` for dependency management\n\n### Local Development Setup\n\n1.  **Clone the repository:**\n    ```bash\n    git clone https://github.com/p67428378-afk/Hotel-Booking.git\n    cd Hotel-Booking\n    ```\n2.  **Switch to the feature branch:**\n    ```bash\n    git checkout feature/SCRUM-36\n    ```\n3.  **Create a virtual environment and install dependencies:**\n    ```bash\n    python -m venv venv\n    source venv/bin/activate  # On Windows, use `venv\\Scripts\\activate`\n    pip install -r requirements.txt\n    ```\n4.  **Run the application (example):**\n    The core logic is within `cancellation_refund_service/main.py`. You can run the example usage to test the refund calculation.\n    ```bash\n    python cancellation_refund_service/main.py\n    ```\n\n### Docker Setup\n\n1.  **Build the Docker image:**\n    ```bash\n    docker build -t cancellation-refund-service .\n    ```\n2.  **Run the Docker container:**\n    ```bash\n    docker run -p 8000:8000 cancellation-refund-service\n    ```\n    (Note: The current implementation is a basic script, not a web service. A full microservice would expose API endpoints.)\n\n## Usage Examples\n\nRefer to `cancellation_refund_service/main.py` for example usage of the `RefundCalculator`.\n\n## Database Schema (Conceptual)\n\n### `cancellation_policy_rules` table\n\n| Column Name       | Type    | Description                                   |\n| :---------------- | :------ | :-------------------------------------------- |\n| `id`              | INTEGER | Primary Key                                   |\n| `membership_tier` | TEXT    | Guest membership level (Bronze, Silver, Gold) |\n| `cancellation_window_start_days` | INTEGER | Start of cancellation window in days before check-in |\n| `cancellation_window_end_days` | INTEGER | End of cancellation window in days before check-in |\
| `refund_percentage` | REAL    | Refund percentage (e.g., 1.0 for 100%)       |\n\n### `refund_transactions` table\n\n| Column Name                 | Type      | Description                                     |\n| :-------------------------- | :-------- | :---------------------------------------------- |\n| `id`                        | INTEGER   | Primary Key                                     |\n| `booking_id`                | TEXT      | ID of the associated booking                    |\n| `guest_id`                  | TEXT      | ID of the guest                                 |\n| `calculated_refund_amount`  | REAL      | The amount calculated for refund                |\n| `original_booking_amount`   | REAL      | The original total amount of the booking        |\n| `payment_gateway_txn_id`    | TEXT      | Transaction ID from the payment gateway         |\n| `status`                    | TEXT      | Status of the refund (Initiated, Successful, Failed, Manual Review) |\n| `timestamp`                 | TIMESTAMP | When the refund transaction was created         |\n| `initiated_by`              | TEXT      | Who initiated the refund (Guest ID or Staff ID) |\n| `reason`                    | TEXT      | Reason for cancellation/refund                  |\n\n## Contributing\n\nFor contributions, please follow the standard GitHub flow: fork the repository, create a feature branch, commit your changes, and open a pull request.\n
